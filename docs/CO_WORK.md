# Gemini co-work handoff

OpenStat Mac is an original MIT-licensed macOS statistics application. This checkout contains source code, tests, fixtures, documentation, and a Python engine. It does not include a verified distributable app or DMG. The repository owner authorized source publication for collaboration at https://github.com/teodorino5/OpenStat-Mac. Use this repository; do not create or publish a second repository.

## Project gate

Phase 0 data foundations are still active and incomplete. Phase 1 statistical procedures must wait until every Phase 0 feature row is verified against reference values. A passing unit suite alone does not satisfy that gate. Add independent, hand-calculated fixtures; ensure acceptance tests load them and carry the matching feature IDs; then run the feature-matrix gate. Never mark a feature verified from expected values generated by the implementation under test. Read `docs/feature_catalog.json`, `docs/FEATURE_MATRIX.md`, and current engine test results before choosing work. The catalog is maintained by the repository owner.

Do not start inferential methods, statistical result charts, or Phase 1 modules. Current engine handshake advertises `analysis_methods: []`. Data transformations and inspections are Phase 0 foundations, not statistical analysis support.

## Separate contribution tasks

Take one bounded task per branch. Confirm file ownership with the repository owner before editing shared UI, RPC, feature catalog, or engine modules. Suitable independent tasks include:

1. Add original reference fixtures and acceptance tests for one unfinished Phase 0 file-format round trip. Keep each format's missing values, labels, and storage limits explicit.
2. Review accessibility, keyboard flow, and English/Czech localization for one assigned native panel. Do not restructure shared navigation or edit generated localization resources without owner coordination.
3. Perform a read-only audit of transitive Python wheel licenses and runtime relocation. Return package/version/license evidence and blockers; do not vendor, bundle, or replace dependencies without approval.
4. Profile one bounded Phase 0 path using the existing benchmark approach. Report machine, architecture, dataset shape, exact command, elapsed time, and memory method. Do not claim five-million-row readiness from a microbenchmark.

## Branch and review rules

After the owner provides the published repository URL, create a task branch from the current default branch, for example `gemini/<short-task>`. Do not commit or push to the default branch, force-push, rewrite shared history, or merge your own pull request. Keep unrelated tasks on separate branches and pull requests. Avoid concurrent edits to the same files. Open a reviewable pull request with a short description, changed-file scope, exact test commands and results, and unresolved limits. Do not upload app binaries or release artifacts as part of source contributions.

## Contributor setup and checks

Use macOS with Python 3.12, `uv`, Swift, and the Xcode toolchain. Run `make setup` to sync the locked engine environment and generate contributor localization resources. The engine uses `engine/.venv`; the app's development runtime points into this checkout. Do not delete or commit local environments or generated build products.

Run focused tests while iterating. Before proposing a pull request, run `make check` for the available source build, complete engine tests and coverage, Ruff, mypy, Swift formatting, Arrow fixtures, smoke executable, feature matrix, and localization checks. Run `make test` with full Xcode to include XCTest. The supported CI workflow also runs `make package` and an Xcode project build without signing on macOS 15 Intel and arm64 runners. Report unavailable or failed checks; do not infer results from workflow configuration alone.

`make package` creates a local contributor app that uses this checkout's Python environment and ad-hoc signature. It is not portable or release-ready. Developer ID signing and notarization are unavailable. Full Xcode/XCTest validation and both Intel and arm64 validation are not yet evidenced for this handoff. A CI matrix definition is not proof that either runner passed.

## Data and licensing rules

Keep source revisions immutable and preserve stable field and row IDs unless an operation explicitly creates a new dataset. Keep raw null distinct from user-coded missing values. State numeric conventions and resource limits in code-facing docs. Do not add arbitrary expression execution, copied vendor code, proprietary samples, screenshots, icons, internal formats, or copyleft components. Preserve third-party notices. A top-level package license is not a complete audit of transitive wheels.

The source-release workflow is a manual source archive path, not a binary release. No published release, notarized build, portable runtime, or verified DMG is claimed here. See `docs/RELEASE.md`, `docs/STRUCTURE.md`, and `docs/RPC.md` before changing packaging or engine boundaries.
