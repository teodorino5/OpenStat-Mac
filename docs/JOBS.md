# Asynchronous jobs

`openstat_engine.jobs.Jobs` runs registered engine operations on one daemon worker. The constructor copies the supplied method registry and rejects invalid names, `jobs.*` names, or non-callable entries with `error.job_registry`. `submit(method, parameters)` accepts only a registered method outside the `jobs.*` namespace and returns `{"job": "<id>"}`. It validates and JSON-clones the parameter dictionary before queuing it. Parameters and results must contain only JSON values with string object keys, finite numbers, nesting depth at most 64, and encoded size at most 7 MiB. Invalid parameters raise `error.job_parameters`; invalid or oversized results end as failed jobs with `error.job_result`. The worker invokes only the registered callable with keyword arguments. It does not load project code or evaluate arbitrary code.

`status(job)` returns `job` and `state` (`queued`, `running`, `succeeded`, `failed`, or `cancelled`). It adds `progress` only after an operation reports a checkpoint. Progress contains actual `processed` and `total` counts plus `fraction`. On success, `fraction` becomes one as a completion marker; counts retain last reported values. A zero total has fraction zero while running and one when succeeded. Successful status includes a detached JSON `result`; failed or cancelled status includes `error: {"key": "..."}`. Unknown IDs and non-string IDs raise `error.job_not_found`.

Registered operations can import and call `checkpoint(processed, total)`. It records the actual counts and raises `EngineError("error.job_cancelled")` when cancellation was requested. It is a no-op outside a worker job. Counts must be integers satisfying `0 <= processed <= total`; invalid counts raise `error.job_progress`. Operations that do not call checkpoints expose no progress. Cancellation is cooperative: `cancel(job)` removes queued work immediately and requests cancellation for running work. A running callable must reach a checkpoint or return before its cancellation takes effect.

The manager allows at most eight queued jobs and retains at most 64 terminal jobs, evicting oldest terminal records first. `close()` is idempotent, cancels queued work, requests cancellation for running work, wakes and stops an idle worker, and returns without joining a running operation. Errors preserve `EngineError.key`; unexpected failures expose only `error.engine_internal`. A cancellation requested before a running operation completes takes precedence over its later return or exception. Parameters, results that fail validation, exception details, and tracebacks are not written to stdout or job status.

Submission errors use locale-independent keys: `error.job_method`, `error.job_parameters`, `error.job_registry`, `error.job_closed`, and `error.job_queue_full`. Invalid checkpoints raise `error.job_progress`; cooperative cancellation raises `error.job_cancelled`. Status and cancellation use `error.job_not_found` for unknown, evicted, or malformed IDs. Integrators should translate these keys at the application boundary.
