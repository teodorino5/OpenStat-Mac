# SPSS, Stata, and SAS interchange

OpenStat uses the audited PyReadStat 1.3.6 package for SPSS `.sav`, Stata `.dta`, and SAS `.sas7bdat` imports. It writes `.sav` and `.dta` files. It does not write SAS files.

The Python API is `import_sav(store, path)`, `import_dta(store, path)`, and `import_sas7bdat(store, path)`. Writers use `export_sav(store, revision, path, overwrite=False)` and `export_dta(store, revision, path, overwrite=False)`. Imports are bounded to 128 MiB per source, 100,000 rows, 1,024 columns, 2,000,000 cells, and 1,000,000 metadata/codebook characters. Exports use the same row, column, and cell limits. They materialize bounded data in memory because PyReadStat writers require pandas or Polars data frames.

Imports keep source variable names, numeric/string values, value labels, supported measurement hints, and discrete user-missing codes. New case IDs are generated because these formats do not carry OpenStat row identity. The response includes `source_metadata` with source format, file label, encoding, variable labels, and source format strings. This report is not stored in the dataset. The response `losses` list names this metadata loss and the row-ID reset. Some readers map both physical null and blank string to the same value; the import response reports that ambiguity. The engine codebook keeps value labels and missing-code declarations supported by its field model.

Imports reject date/time-formatted variables, tagged missing values, non-degenerate SPSS missing ranges, multiple-response set definitions, unsupported variable types, duplicate names, and inputs over limits. These cases do not map safely to the current typed field model. Formula execution is not part of this adapter.

Exports preserve numeric values only when integer values fit the exact range of binary64 (`-2^53` through `2^53`). Larger integers fail with `error.readstat_precision`. Multiple-response fields fail rather than being flattened. Export reports loss of OpenStat field and row IDs, dataset context, observation unit, and engine missing-code declarations. String columns report `null_empty_string_distinction`: both SAV and DTA writers map physical null and empty text to empty text. Value labels are written when their keys fit the target numeric/string representation. Source file labels, original encodings, formats, and source metadata are not round-tripped. The tested PyReadStat 1.3.6 readers/writers preserve negative zero and a 3,000-character DTA string. These checks do not establish behavior for every vendor version.

Errors use these stable keys: `error.readstat_file`, `error.readstat_limit`, `error.readstat_schema`, `error.readstat_type`, `error.readstat_date_format`, `error.readstat_missing_range`, `error.readstat_tagged_missing`, `error.readstat_multiple_response`, `error.readstat_name`, `error.readstat_precision`, `error.readstat_export`, and `error.field_name` for illegal imported identifiers.

Tests create original SAV and DTA files with the audited writer and compare imported/exported values against literal expectations. No vendor sample datasets or proprietary source material are used. SAS import remains unverified by a generated fixture because PyReadStat has no SAS writer; do not treat its format support as independently fixture-verified.
